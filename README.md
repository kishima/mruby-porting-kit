# mruby porting kit

Machine-checkable material for porting the [mruby](https://github.com/mruby/mruby) 4.1 VM
to another language or environment. It accompanies the book *Deep dive into mruby*
(Japanese, Kishima Craft Works, 技術書典21, 2026-11) but is usable on its own: everything
here is either generated from the reference mruby binary or copied from the mruby tree.

The idea being tested: **with the book and the mruby source, a person or an AI should be
able to port the VM to any environment in one continuous session and pass mruby's own test
suite.** The `experiments/` directory records how far that got.

| directory | content |
|---|---|
| `dataset/` | one JSONL record per opcode (119): definition, operands, reference dumps, `src/vm.c` excerpt, version history |
| `samples/` | the Ruby scripts the book's examples are taken from |
| `fixtures/` | scripts with the reference `mrbc` output (`.mrb`, `.dump`) and the reference `mruby` stdout (`.out`); a port should reproduce `.out` byte for byte |
| `mrbtest/` | mruby's own `test/assert.rb` and `test/t/*.rb` (MIT), compiled; how to run them outside mruby (`DRIVER.md`); the reference's own per-file results |
| `docker/` | the Dockerfile of the verification image (`kishima/mruby:4.1.0-rc2`) |
| `stages.md` | the porting stages of the book's porting chapter: goal, what to read, symptoms and causes, which test files should pass |
| `experiments/` | records of actual ports made with this kit |

Reference version: mruby `4.1.0-rc2` (2026-09-11). Regenerated by the book's `tools/build_kit.rb`; do not edit by hand.

Ports made with this kit: [SabiRuby](https://github.com/kishima/sabiruby) (Rust).

Issues and reports of ports to other languages are welcome; a response is not promised.
